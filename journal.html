  1. v1.7.2 二〇二六年九月二十三日 修 复
    • 文本档案也有大纲了：Markdown（.md）、纯文本（.txt）与代码档案的阅览栏左侧多了一个「≡ 大纲」。Markdown 的 # 标题会自动分级编号（## 是 1.1，它下面的 ### 是 1.1.1）；代码档案认的是 def / class / function / CREATE TABLE 这类定义行，后面还标着「函数 / 类 / 表」。点一下条目正文就跳过去 —— 在「修订」里写代码时是光标直接落到那一行，接着就能改。档案里没有标题时会给一句"怎么写标题"的引导，不留一片空白。
    • 阅览栏多了「全屏」这一档：原来点「加宽」最多只能到"留着侧栏位置"的宽度，左边永远空出一条；把侧栏收起来之后它居然还按侧栏宽度扣，空出的那一整条其实是白留的。现在按钮是三档循环：默认 → 加宽 → 铺满整窗（侧栏区域也一起用上）。侧栏收起时「加宽」也直接用满可用宽度。
    • 侧栏收起后，左边那段留白还给内容：档案卡片的左内边距从 40px 收到 16px —— 收起侧栏本来就是"我要更多地方看文件"，结果内容还缩着一截（顶栏那点不动，左上角浮着展开把手）。
    • 错题本的题目框自己能滚了：题目很长时不再把整页撑开、把「一键复习」那排按钮顶到屏幕外面 —— 题目框自己滚，卡片标题与按钮始终留在视野里；滚轮也给错题本详情区与复习弹窗挂了兜底。
    • 官网多了「便携版」专页：免安装、自带 Python 3.13 与常用库（numpy / pandas / matplotlib / openpyxl / requests，还配了中文字体），资料存在程序旁边的 data 里 —— 拷进 U 盘，插到任何一台 Windows 电脑上双击就能用，换台机器插上接着干。下载、目录结构、与安装版的区别、注意事项都写在新页面上：便携版使用指南。
    • 修掉连接列表"凭空消失"：连上数据库后连接列表会自动收起（把宽度让给编辑区），可它的展开入口长在工作区工具条上 —— 一断开连接、工作区隐藏，入口跟着没了，列表又被收起状态藏着，于是整个界面里再也找不到连接列表、也连不上别的库。现在未连接时列表一律放出来（断开之后你正要挑下一个连接嘛）。
  2. v1.7.1 二〇二六年九月二十三日 新增
    • 笔记本有了 Jupyter 那一套快捷键：先点一下格子的空白处（或按 Esc 从输入框退出来），就进了「命令态」—— a 在上方插一格、b 在下方插一格、dd 删掉这一格、x 剪切、c 复制、v 粘到选中格的正下方、z 撤销单元格操作（剪掉的、删掉的、粘出来的都能退回来）；Enter 回到输入框，m / y 在标题格与代码格之间来回切。在输入框里打字时这些字母就只是字母，不会凭空插出一格。工具条上也放了一个「⌨ 快捷键」，随时点开照单子按。
    • 每个格子前面那道竖杠会表达状态了：蓝色 = 选中了这一格（现在按字母是在操作格子），绿色 = 光标就在这一格里（正在打字）。一屏里只有一格会变色，扫一眼就知道现在按字母是插格还是打字。
    • 补全改成按 Tab 唤起：以前敲一个字就往外冒候选框，连着写代码被一个接一个地打断；现在打字时安安静静，想补的时候按一下 Tab 才弹出来。只有唯一候选时（比如 retu）按一下就直接补成 return；没有候选可补时 Tab 仍然是缩进 —— 写代码按 Tab 缩进的老习惯一点没变。Ctrl+空格 也还能随时唤起。数据库「SQL 查询」页保持原来的敲字即弹（那里补的是库名表名列名，随手就有用）。
  3. v1.7.0 二〇二六年九月二十三日 新增
    • 软件能直接当笔记本用了（.ipynb）：Jupyter 的笔记本档案现在打开就是笔记本 —— 一格一格地写、单独运行某一格、格子之间共享变量、输出与插图都留在格子里。
    • 笔记本的侧边大纲：像 Jupyter 的目录那样自动编号（## 变成 0.1，它下面的 ### 是 0.1.1），只列标题不塞代码，可折叠、点一下跳过去，滚到哪一节就高亮哪一节。
    • 笔记本里也有上色、补全与中文报错：关键字、字符串、数字各自颜色；补全沿用"导包后的成员也能补"那一套；出错给的是中文解释（第几行、什么毛病、怎么改），不是一坨英文 traceback。
    • 错题本里的 SQL 题能在指定的库里重做了：复习弹窗多了一行「在哪运行」（选连接 + 选库），点「运行作答」真的在那个数据库里执行，结果按表格回来，摘要写清「在 哪个连接 / 哪个库 中执行」；没选连接时会明说"这次只做了语法初检"，不让你以为已经跑过了。选过的连接记在这道题上，下次重做直接选中。
    • 每份代码档案有了固定的工作目录：以前运行是在一个临时目录里跑、跑完就把目录删掉 —— 脚本存下的 result.csv 你再也找不到；而库里的档案在磁盘上是哈希名，一眼认不出谁是谁。现在每份代码档案有一个以档案名命名的工作目录：源码（原名）、你放进去给它读的数据文件、它生成的结果都在这里，跑完不删。open("data.txt") 这种相对路径也终于能用了；终端装的包与「运行」在同一个目录，脚本直接就能 import。
    • 运行结果里直接告诉你产物在哪：跑完在输出区上方给出工作目录的完整路径，附「打开工作目录」「定位源码」，并列出这次生成了哪几个文件（这些文件照旧自动入档，库里也看得见）。
    • 字号旁边多了「📁 文件夹」：只有编程类档案才出现，一点就在资源管理器里打开这份代码的工作目录 —— 找它读写的文件不用再翻目录。
    • 补全不再是"写死的词表"：以前只认内置那几百个名字 —— import pandas as pd 之后敲 pd. 什么都没有。现在会问真实的 Python 环境（真 dir()）：导包后的成员、import 行该写哪个模块、from x import … 有哪些名字都给；新装的包立刻生效（结论缓存十分钟，打字不卡手）。
    • 修掉三个"点了没反应"：① 「知识点」小窗其实每次都打开了，但被阅览栏盖在下面（从 v1.6.1 就有的老毛病）；② 笔记本里内容多的格子显示不全（被上色层裁掉，只显示两行高）；③ 打开文件夹 / 定位文件失败时一声不吭，现在会明确告诉你原因。
  4. v1.6.2 二〇二六年九月二十三日 修复
    • 更新提示靠谱了：以前查过一次就把结论缓存一整天 —— 官网当天更新了，你再打开软件也看不到；现在缓存只留一小时，而且换了版本就作废，所以不会再出现「装的明明是最新版，软件却还说有新版」这种自相矛盾的话。软件一直开着的话，每 3 小时还会静默复查一次，不用为了看更新去重启；检查不通时会如实写「这是上次的结论」，不把旧结果说成刚查的。
    • 修掉一处编辑面残留：先打开代码档案（.py 等）的「编辑」，再切到别的档案的「编辑」时，代码高亮那层会继续留在界面上显示上一份档案的代码，还把新的编辑面挤成半截 —— 现在它跟着编辑框一起显隐。
    • 「边看边改」「附属文件」不再对所有档案露面：它们只对 .html 档案有意义 —— 上一版是「置灰 + 写明原因」，这一版干脆不出现，不给用不上的入口占位置。
  5. v1.6.1 二〇二六年九月二十二日 改进
    • 「边看边改」只留给 HTML 了：上一版把左右分栏开给了所有档案，结果编辑区被分掉一半宽 —— 而代码档案的「预览」本来就是源码，一边改一边看没有意义。现在只有 .html 档案会分栏（它的预览就是最终排版，改一行右边立刻变），其它档案一律整宽编辑；在不适用的档案上，那个按钮会置灰并写明原因，不会点了没反应。
    • 文本文件的「代码块」在预览里能看见了：以前 .md / .txt 这类档案的预览只显示原文 —— 代码块只剩一排 ``` 标记、标题也只是一排 #。现在预览默认渲染成排版：标题、列表、引用、表格、代码块都在，右上角还多了「源码」，一键切回原文对照。纯代码档案（.py 等）照旧只看源码，不会被当成 Markdown 解释。
    • 修掉一处会让你以为「编辑区不见了」的问题：关掉「边看边改」时，编辑区所在的那一栏被整栏隐藏，编辑标签会一片空白（默认开着分栏，所以一直没露出来）。现在两栏各按标签分工 —— 预览标签看预览、编辑标签看编辑区。
  6. v1.6.0 二〇二六年九月二十二日 新增
    • 写代码终于有颜色了：代码档案的编辑区、数据库里写 SQL 的框、工程里的文件，边写边着色 —— 关键字、内置函数、字符串、数字、注释各是一种颜色（SQL 的 SELECT / FROM / WHERE 也认）。做法是在编辑区底下铺一层上色层、原输入框的文字设为透明，所以保存、草稿、补全、Ctrl+滚轮缩放全都不受影响；超过 200 KB 的大文件自动不上色，免得打字卡手。
    • HTML 有了真预览，还能边看边改：以前点开 .html 只是一段灰扑扑的源码。现在它能按网页渲染出来（出于安全，页面里的脚本默认不执行），编辑标签下还能左右分栏 —— 左边看效果、右边改代码，改完点保存即刻生效。
    • HTML 可以引用外部 CSS / JS / 图片了：一份 HTML 档案现在能带上自己的附属文件（编辑标签栏的「📎 附属文件」里添加）。档案里照常写 <link href="style.css">、<img src="img/logo.png"> 这样的相对路径即可，预览时会自动找到对应文件；删除档案时附属文件一并清走。
    • 文本文件的代码块与引用：富文本工具栏的段落下拉里多了「代码块」和「引用」，样式也补齐了（等宽字体、灰底、可横向滚动）。Markdown 的 \`\`\` 围栏往返不再丢结构 —— 代码里的 *、_、# 也不会被当成格式标记改掉。
    • 数据库：对象树能收起来了，工具条上「⊟ 对象树」一点即收，把宽度整份让给编辑器；树的宽度拖动后也会记住（下次打开还是你调的那个宽度）。
    • 「建表」变成了下拉：建表 / 建数据库 / 建视图各给一份可直接改的草稿。建库的写法按驱动出（MySQL / PostgreSQL / SQL Server 各不相同），SQLite 是单文件库、没有这一句，那一项会置灰并说明原因。
    • 修掉两个问题：① 对象树「草稿（未保存）」里的条目点删除删不掉（它走错了接口，删的是同名正式查询，草稿原封不动）—— 现在「✕」与右键都会真正丢弃草稿，并解除还开着的那枚页签的关联。② 作业模式或窗口拉窄时，数据库工具条最右边的按钮会被挤出可视区 —— 现在工具条会换行，按钮不再被裁掉。
  7. v1.5.2 二〇二六年九月二十二日 修复
    • 档案目录里「文件一多就滚不动」修好了：这是界面自身的一处疏漏 —— 档案视图少了约束高度的那一步，卡片一多，网格就被内容顶出可视区，而外层并不滚动，于是滚轮怎么转都没反应（档案少时不满一屏，所以一直没暴露）。现在滚动落回目录本身，几十、几百份档案都能顺滑滚到底。
    • 数据库连接成功后那条竖窄条不再占地方：连接成功时连接列表会自动收起（把宽度让给数据与编辑器），原来在中间留一条 30px 的竖条用来重新展开 —— 它白占编辑区宽度。现在这条不显示了，重新展开的入口挪到工作区工具条上的「⊞ 连接列表」（只在收起时出现，点一下即展开）。编辑区因此宽了约 40px。
  8. v1.5.1 二〇二六年九月二十二日 新增
    • 设置里能定「默认导出路径」了：以前导出档案只会落进系统的「下载」文件夹，改不了。现在打开设置 → 存储 → 默认导出路径，点「选择…」挑一个文件夹（手敲路径也行），之后导出档案（txt / md / csv / xlsx / docx / json…）与数据库表时，文件直接写进那儿，写完会告诉你确切路径；想改回去就点「清除」。文件夹不存在会自动建好，留空即回落到系统的「下载」文件夹。
    • 顺手把导出收口到一处：档案导出原来走的是「让浏览器去下」，那条路只能落到浏览器的下载目录；现在统一改走软件直接写盘，所以「默认导出路径」才真的管得着。导出完成后如果写到了别处（比如那个目录当前不可写），界面会明确提醒，不会悄悄换个地方存。
  9. v1.5.0 二〇二六年九月二十二日 新增 除弊
    • 多文件编程工程：以前一份档案就是一个文件，scrapy 那种「一个项目好几个文件、靠目录结构互相导入」的项目放不进来。现在档案目录里多了一类工程卡片 —— 点开是左侧文件树、右侧编辑器的工程视图：新建 / 改名 / 删除 / 上传文件，多标签同时改几份。文件是数据目录里一个真实目录，原始目录结构与文件名都保留，所以 from mypkg.items import X 这类相对导入照常可用。新建时可选空白 / Python 包 / Scrapy 爬虫三种骨架，scrapy 那套连 scrapy.cfg、settings.py、spiders/ 都替你铺好。
    • 命令在工程根下跑，能存好几条：每个工程可以存多条命令（比如「跑爬虫」= python -m scrapy crawl example），点「运行」时工作目录就是工程根 —— scrapy 靠这个找 scrapy.cfg，工作目录错了整个项目就跑不起来。
    • 依赖装进工程自己：工程视图下方有命令输入框，pip install -r requirements.txt 装进的是这个工程自己的 .packages，既不污染系统 Python，几个工程之间也不会打架；装完直接能 import（运行时会自动挂进 PYTHONPATH）。想清干净就「更多 → 清空已装依赖」。
    • 更新下载不再挡着界面：以前下载进度画在中间的弹窗里，而弹窗是模态的 —— 上百兆的包要下几分钟，这几分钟什么都干不了。现在一点「下载并安装」就把弹窗收掉，进度挪到右上角的小浮窗：百分比、已下 / 总量、实时速度、预计还要多久都在上面，还能收成一条。想关软件也随时能关（只是下载会中断，浮窗里写了这句）。
    • 修好「点立即安装没反应」：两处原因。一是没有安装包时它一声不响就退出了 —— 现在会明确告诉你「还没下载好」；二是原来走的是静默安装（不弹任何界面），而静默模式下安装包装完不会把程序拉起来，看着就像什么都没发生。现在改成弹出安装向导：能看见进度与完成页，装完还能勾选直接运行；主进程退出也加了兜底，不再出现「该退不退、装不进去」。
    • 下载提速：官网这台服务器在境外，国内跨境单连接被丢包拖死（实测只有 12 KB/s）。做了三件事 —— 服务端启用 BBR 拥塞控制并调大 TCP 缓冲（单连接 12 KB/s → 357 KB/s）；官网下载按钮改成 8 段并发（实测约 1 MB/s，115 MB 的包两分半，下完自动比对 SHA-256）；软件内的更新包下载同样分片。
    • 顺手修的两处：命令里带引号不再被 Windows 吃掉（python -c "print(1)"、pip install "scrapy>=2.0" 这类以前会被截断）；主页更新手记第三条的排版错乱（早先删旧版本时留下的残片，把列表格式弄坏了）。
  10. v1.4.1 二〇二六年九月二十二日 新增 除弊
    • 写一半就把软件关了，内容不再丢。以前只有点了「保存」才算数，写了一半关掉（甚至断电、在任务管理器里结束进程）就全没了。现在编辑区里的东西停手一秒多就自动存一份草稿，重开还在。
    • 查询：未保存的查询会在连上数据库时自动回到页签里（最多先回来 8 份，按最近改过的排）；它们是「未保存」状态，点「保存查询」就变成正式查询。
    • 新增「草稿箱」：对象树的「查询」下多了一个「草稿（未保存）」文件夹 —— 关掉的、暂时不想管的、属于别的库的草稿都在这里，点开接着写，右键可以「存为正式查询」或「丢弃」。正式保存之后草稿自动消失，不会下次又冒出来一份「未保存」。
    • 正文修订、表格、导图、文稿、演示、作业面板同样受保护：打开这些编辑面时，如果发现上次留下没保存的改动，会在编辑区上方摆一条提示 —— 「有 X 分钟前未保存的改动，要接着写吗？」，点「恢复」把内容接回来，点「丢弃」才真的扔掉。这里刻意不做成「悄悄填回去」：那会在你没注意的时候盖掉刚写的东西。

    • 知识点本 —— 读到哪里，随手记成知识点：在正文里划一段字，浮条上点「＋ 知识点」，选个分类、起个标题就存下了。同一分类下标题相同会自动归到一起，不必手工整理目录。检索台里以「分类 → 标题 → 条目」两层树查看，条目可「回到来源」跳回原文。
    • 错题本 —— 做过一遍，才是真的会了：划出题目与答案两段（答案可用「；」分成要点）存进错题本，记下题型与科目。检索台点一键复习：先只给题目、把答案藏起来，你做完提交后三框对照 —— 上框题目、左下参考答案、右下本次作答，并用要点命中率给个参考。若这道题来自代码档案，复习时可直接调用对应语言的编译器现场跑一遍作答。
    • 两者都按文件后缀自动分类：来自 .py 的进 Python 类，来自 .xlsx 的进表格类，也可在加入时改到别的分类；分类树上直接标出「该分类可用哪种编译器重做」。
    • 编辑档案时的知识点小窗：阅览栏工具条上多一个「知识点」按钮，点开是贴在栏内一侧的窄窗，列出当前分类下的知识点；正文自动让出这一列，不遮住你要读的字，可加宽、可搜索，也能就地从这里再添一条。
    • 完整性与来源校验 —— 拿了这份，先看它是不是原版：每次构建生成唯一的构建编号，并对关键程序文件（前端包与后端包）计算 SHA-256 写入校验清单；软件里打开设置 → 关于即可自查「是否与官方构建一致」，不一致会指出具体是哪个文件被改过。校验码同时公布在本页，可自行比对下载到的安装包。说明白它的边界：没有代码签名证书时，这一层挡不住专业逆向者 —— 它的价值是让「随手改一改就冒充正版」变难且必留痕，并为后续接入代码签名留好接口。
    • 检索台改版：原先的「最近入档」「有批注」两个入口，换成知识点本与错题本，占位处直接显示条数。
    • 顺手治了一个卡顿：打开设置面板时，程序要在本机翻找各类编译器与解释器，过去这一下会把整个程序堵住十来秒——连「关于」页的完整性核对都得排队干等。现在改成后台悄悄探、探完自动补上，设置面板即刻可开，关于页立刻出结果。
  19. v1.2.2 二〇二六年九月二十一日 新增 改进
    • 报错不再是一屏英文 —— 跑代码出错、连库出错，一律译成中文：先给一句人话结论（「用了一个还没定义的名字」「除数为 0，不能相除」），再指出第几行、第几列，把那一行代码连同 ^ 指示一起贴出来，最后给一条怎么改的建议。原始英文报错收进「查看原始报错」折叠里，要对照时随时展开。
    • 认得十二种语言的报错：Python、JavaScript / TypeScript、C / C++、Java、Go、Rust、Shell、Ruby、PHP、PowerShell。Python 的 NameError 会顺手告诉你「猜你想写 total」；Go 会点出「变量声明了却没用」；Rust 直接按错误码解释（E0425 找不到值、E0308 类型不匹配…）；C 的报错会替你分清是「少了分号」还是「少了右花括号」。
    • 数据库报错同样说中文，并在 SQL 里标出出错的位置：MySQL / MariaDB、PostgreSQL、SQL Server、SQLite 四家的错误码各有对照表——表不存在、列名拼错、主键重复、外键拦着不让删、值太长装不下、必填字段没给值、事务死锁，都译成人话。MySQL 的语法错误靠它给的 near '...' 片段定位，PostgreSQL 用它给的字符偏移，直接把 ^^^ 标在你写的那条语句上。
    • 表名、列名会替你要点出来：报「表不存在」时说明是哪个库里没有哪张表；「列不存在」时报出具体列名；重复键会连值和键名一起说清楚。
    • 行编辑、翻页、导出出错也一并处理：不管是手写 SQL、在表格里改一行、翻页看数据还是导出，出错都给同一套中文说明与位置提示。
    • 「报错位置不对」这件事也一并治了：解析器报的从来是「它在哪里发现不对」，不是「你哪里写错了」。最常见的元凶是中文输入法下的全角逗号——MySQL 会把它当成别名的一部分吃进去，于是报错点往后挪一行。现在会直接告诉你：第几行末尾那个「，」该写成半角，而且报错位置因此偏下了一行；万一上一行真是漏了逗号，也会指回上一行去。
    • 位置指示按显示宽度对齐：源码行里带中文别名（如 as 总成绩）时，^ 指示线过去会往左偏——汉字占两个字符宽，补空格却只按字数算。现已按显示宽度精确对齐到出错的那个字上。含制表符的行同样对得准。
    • 运行成功时不出任何诊断——没消息就是好消息。
  20. v1.2.1 二〇二六年九月二十一日 新增 改进
    • 新增「打字即补全」——写代码时不用再记单词：在代码档案的修订页、以及数据库工作台的作业面板里敲字母，光标下方即列出候选。候选有四类：这门语言的关键字、内置名、对象成员，以及当前文件里已经出现过的名字（按出现次数排前）。写过的变量、函数名、自己起的类，都会自动进候选。
    • 对象成员也认：敲 document. 列出 getElementById / querySelector 等；Math.、String.、os.、fmt. 各有自己的成员表——JS / TS / Python / C / C++ / C# / Java / Go / Rust / Shell / HTML / CSS 都在内。
    • 数据库「SQL 查询」页同样能补：SQL 关键字与函数（插入时自动大写）、当前连接里的库名与表名，并且认得 FROM students s 这种别名——敲 s. 直接列出这张表的真实列名；SELECT 列表、WHERE 里敲裸列名也能补（列名从你连的那个库里现取）。
    • 按键照着手感来：Tab 或 Enter 接受、↑↓ 选择、Esc 关闭、Ctrl+空格 手动唤起；没有候选时 Tab 仍然是四空格缩进——原来的手感一点没变。候选面板贴着光标那一行的正下方弹出，跟着你走。
    • 设置里可开关：「偏好设置」新增「文本补全」一栏——可以整个关掉（只留缩进），也可以只关掉「本文件里出现过的名字」这项候选。
  21. v1.2.0 二〇二六年九月二十一日 新增 修复 改进
    • 新增「档案内查找」——任何档案都能 Ctrl+F：文本、代码、Markdown、网页、Word 文稿、表格、演示、思维导图，一律可查。命中处全部点亮、当前一处用朱砂标出，Enter / ↓ 下一处、Shift+Enter / ↑ 上一处、Esc 退出，还能一键切换「区分大小写」。找一段话、一个函数名，不必再靠眼睛一行行翻。
    • 命中点自动带到眼前：滚动位置按命中文字本身计算（不是按它所在的段落），命中在哪就翻到哪；思维导图里命中节点若在画布之外，会把画布直接平移过去——放大过的导图也能一查即到。
    • 分屏与作业模式各查各的栏：点哪一栏就查哪一栏，互不串台；换标签页、换档案、关掉阅览栏时查找条自动收走。
    • 修订页同样能查：文稿编辑器里直接高亮；代码档案的修订框按 Enter 即选中命中词并滚到眼前。
    • 修好了「表格预览内容一多就变成竖条」：列宽原由浏览器按容器宽度摊派，8 列的表每列只剩 43~80px，一格 28 个字被折成 7 行，一行高 157px，整张表 6500px 高——数字、学号都被拆成一列一个字。现在列宽有下限、表格横向铺开、左右滚动查看，行高回落到 77px，表格终于像表格了。
    • 表格预览新增行列提示与吸顶表头：表格上方标出「共 N 列 × M 行」，往下翻几十行时列名始终停在顶部。
    • 官网头部导航新增「更新手记」入口，改了什么一眼直达。
  22. v1.1.6 二〇二六年九月二十一日 修复 改进
    • 修好了「表格文字一多就看不见、也改不动」：此前列宽被表格布局压到 120px，长内容只露出开头几个字（实测 1962 字的单元格仅显示 4.8%）。现在列宽锁定 180px、表格总宽按列数显式给出，单元格换成可换行、可自动增高的输入框——文字多长就铺多长，整段看得见、点得进、改得动。

    • 修好了「有些文件的预览滚不动」：思维导图过去的普通滚轮什么都不做，导图一放大就出不来——现在滚轮直接平移画布（Ctrl+滚轮 仍是缩放，画布装得下时自动放行给外层翻页）。

    • 修好了表格预览的滚动条抢滚轮：横向滚动条原先常显，并把纵向也算成自己的滚动范围；现改为按需出现，纵向交还外层。
    • 新增滚轮兜底：万一预览里的内嵌元素（内嵌网页 / 图片 / 图形 / 宽表格）把滚轮吃掉了，会自动把这一格位移补给预览容器——保证「任何文件的预览都能用滚轮滑动」。
    • 作业模式面板一并纳入滚动条兜底，长文档并读不再卡手。
